# Native compiler and persistent modules in UTM

This milestone replaces the **compiler bottleneck** for a separate native source
session. It does not yet boot the complete upstream ZealOS system. The original
`hc` / `runzc` / graphics / RedSea shell remains available for regression checks.
Pi is outside this milestone; its diagnostic image does not link this runtime.

## What is being integrated

- The pinned Aiwnios lexer, parser, optimizer and ARM64 JIT run **inside the
  freestanding guest**. No macOS/Linux services, SDL or hosted HCRT are linked.
- A session retains global symbols, types, functions and allocations across
  independently compiled source files. Local call frames and recursive calls
  are generated by the imported backend.
- A host allocator supports arbitrary-order `Free`, splitting and coalescing.
  Its 16 MiB data and 4 MiB executable arenas are separate from the legacy
  frontend's memory. `Free(NULL)` is a no-op. Allocation failure invalidates
  the native session and returns to the shell.
- A read-only, deterministic source archive is a third Limine module in both
  the ISO and GPT/EFI boot image. Includes read files from this archive.
- On the 128 MiB PCI/UTM boot disk, `disk:Name.ZC` reads a separate 32 MiB
  source partition. It has path names, append-only updates and checksums; it
  does not consume RedSea's eight root entries. `zput` saves source there and
  the loader reopens it after reboot. Older 64 MiB and ISO/MMIO images still
  read their flat legacy RedSea files through the same `disk:` prefix.
- `upstream/pinned/Kernel/QuickSort.ZC` is the **complete unchanged file** from
  public ZealOS commit `eee210f4379ba3d00b47507f336a158eefb2c993`. The test caller and
  bootstrap declarations are separate local files. This is not another edited
  `Lite` version of the upstream algorithm.
- The same public commit supplies unchanged `Kernel/KernelA.HH`, `Kernel/KernelB.HH` and
  `Kernel/KMathB.ZC` in the source archive. The headers declare the original
  task and memory model; most `KernelB` x86 intrinsics and port-I/O services
  still need ARM64 implementations. `KMathB` now loads and its tested
  single-task random and math path runs through ARM64 bindings.
- Unchanged `Kernel/KTask.ZC`, `Kernel/Sched.ZC`, `Kernel/Job.ZC` and
  `Kernel/MultiProc.ZC` are pinned as references for
  the task API. Their x86 assembly and full kernel dependencies are not loaded;
  an ARM64-specific KTask source overlay is exercised by a focused module probe.
  A separate `System/TaskBridge.ZC` declares the upstream `Spawn`, `Yield`,
  `TaskValidate`, `Suspend`, `IsSuspended`, `Kill`, `BirthWait`, `DeathWait`,
  `TaskWait`, `ZcTaskWaitTimeout`, `TaskMessage`, `MessagePost`,
  `MessagePostWait`, `Message`,
  `MessageScan`, `MessageGet`, `FlushMessages`, `TaskExe`, `JobQueue`, `SpawnQueue`,
  `JobsHandler`, `JobResScan`, `JobResGet`, `Sleep`, `Exit`, and `TaskEndNow`
  signatures for a bounded, single-CPU cooperative subset.

The Aiwnios import is pinned to `e155e87a4a4ddae4cd7f25685d9db8869fd45a40`.
`third_party/aiwnios/PORT.patch` records local changes. `python3
scripts/check-upstream.py`
reverses that patch in a temporary directory and checks the original hashes.
Licenses ship in the source archive.

The original source pin was a local fork commit that could not be fetched from
the public ZealOS repository. The current public commit has the same QuickSort
SHA-256 and makes every pinned file independently retrievable.

## Use it

Boot the refreshed UTM image and run `zcheck`. It resets the native session,
loads the upstream module and separate callers, then reports the integration
checks. A successful session remains available at the prompt.

```text
zcheck
zstatus
zcall SortChecks
zc I64 Answer(){return 6*7;}
zcall Answer
```

`zcall Answer` should display `zc => 0x000000000000002a` (42).
`zc` executes top-level declarations and statements; a `return` belongs inside
a function. `zcall` invokes a no-argument integer-returning function.

For a fresh manual load:

```text
zreset
zload /Kernel/QuickSort.ZC
zload /Tests/SortCaller.ZC
zcall SortChecks
```

The expected result is `0x3f`. Plain `zload` paths resolve from the boot archive;
`disk:` paths prefer the native source partition and fall back to RedSea for
flat legacy names. A native deletion masks a same-name RedSea file for `disk:`
loads. `runzc` continues to use the original RedSea/tiny-frontend path.

To save and run a small native module on the virtio disk:

```text
zvol
zput Native.ZC I64 DiskValue(){return 42;}
zload disk:Native.ZC
zcall DiskValue
```

Restart the VM, then repeat the last two commands. The result remains `0x2a`.
`zput` accepts one shell line; `\n` inserts a source newline. `zvol` reports
whether the native partition is present. The disposable PCI harness writes
files in `App/` and `Lib/`, resolves a relative `../Lib/` include, and reloads
them after a full guest restart. It also checksums the seeded 114 KiB
`KernelA.HH` via `zverify Kernel/KernelA.HH` and loads upstream QuickSort from
the source partition. The ISO harness continues to test the RedSea fallback.
`zls` lists the latest live native sources and reports record/sector use;
`zrm App/Native.ZC` hides one from future loads. Already compiled functions
remain in the current session until `zreset`.
`zgc` copies the latest files and deletion records to the inactive 32 MiB
source bank, verifies the copy, and switches banks in the guest. `zvol`
reports the active bank and generation. The original bank remains available
until the next compaction, and `make utm` preserves both banks.

To create or revise a source file entirely in the guest, use the modal line
editor:

```text
zedit App/Answer.ZC
a I64 Answer(){return 42;}
p 1 1
wq
zload disk:App/Answer.ZC
zcall Answer
```

At `edit>`, `a` appends a line; `i N <text>` inserts before line N;
`c N <text>` replaces one line; `d N` deletes it; and `p [N [count]]` prints
numbered lines (20 by default, at most 50). `w` saves and stays in the editor,
`wq` saves and returns to the shell, `q` exits only when unchanged, and `q!`
discards unsaved edits. The editor opens the latest native source, checks its
CRC, and writes a new version on save. It can hold a 4 MiB file, but each
entered line still fits the 511-byte shell input limit. On ISO/MMIO boots,
`zedit` reports that the native partition is unavailable.

For a larger file while UTM is running, prepare pasteable transfer lines:

```sh
python3 scripts/send-zc.py /path/to/Module.ZC Home/Module.ZC --emit
```

In UTM Terminal 1, paste the printed `zrecv` command, wait for `ready`, then
paste each following hex line after the previous `ack`. The final message is
`zrecv: saved Home/Module.ZC bytes=...`; use `zload disk:Home/Module.ZC` and
`zcall` to run it. `--serial /dev/tty...` sends and waits automatically when
the guest serial port is exposed as a raw TTY or PTY. The transfer requires the
native source partition and checks CRC-32 before committing a new record. It
supports 1 byte to 4 MiB, with 128-byte acknowledged chunks and a two-minute
wait for each chunk in the guest; it is a bootstrap transfer protocol, not an
editor. If a paste is malformed or times out, start a new `zrecv` command; an
earlier version of the file remains available.

For larger source files, stop the VM and use the host importer on its disk image:

```sh
python3 scripts/source-volume.py put /path/to/VM/Data/Omarchy-QEMU.raw \
    /path/to/Module.ZC Home/Module.ZC
python3 scripts/source-volume.py inspect /path/to/VM/Data/Omarchy-QEMU.raw
python3 scripts/source-volume.py delete /path/to/VM/Data/Omarchy-QEMU.raw \
    Home/Module.ZC
python3 scripts/source-volume.py compact /path/to/VM/Data/Omarchy-QEMU.raw
```

`make utm` preserves both the old RedSea bytes and an existing native source
partition. The source partition is seeded from the pinned source archive on
first migration; later image refreshes retain user edits. The stopped-VM
`compact` command rewrites the active native bank, retaining live files and
deletion records while reclaiming superseded file versions. It verifies live
file checksums and replaces the image only after writing a complete copy.

`python3 scripts/check-compat.py --probe-upstream` records the current results
in `build/check-upstream-probe.log`. The unchanged 113,880-byte `KernelA.HH`
now loads: the compiler handles its class-scoped `$$` layout cursor, evaluates
its layout `#assert`s, selects the `#if FALSE` class definitions, and accepts
quoted `#define "Help/Category"` metadata. After `KernelA`, the unchanged
`KernelB.HH` also loads its declarations. `_intern` functions remain unbound
unless a compatible ARM64 host binding exists; the compiler rejects a call
to an unbound intrinsic, named external function, or external data. The
`KernelB` declaration of `MemCopy` retains its compatible bootstrap binding,
while the x86 `SwapI64` signature does not match and remains unavailable.
Loading headers is not the same as running the ZealOS kernel or validating
every class against the x86 ABI. The bootstrap binds `pow10_I64` to a
powers-of-ten table corresponding to upstream `KMain.ZC`. With both headers
loaded, unchanged `KMathB.ZC` also loads. Its `Fs` call returns one root
`CTask` whose field offsets are checked against the parsed `KernelA` class;
the pointer lives in `TPIDR_EL1`. A bounded cooperative bootstrap can now
create four more `CTask` instances with separate 64 KiB stacks and switch
between them. It saves the ARM64 callee-saved integer and FP registers, SP,
FPCR and FPSR. `Spawn` starts a callback with its `data` pointer, a checked
parent and a task-owned heap; the callback's allocations are reclaimed when it
returns. `Yield`, `TaskValidate`, `Suspend`, `IsSuspended` and `Kill` use the
same task contexts. Suspended tasks remain valid but are skipped until resumed;
`Kill(wait=TRUE)` waits for immediate child teardown when no callback is
installed; with a callback it waits for the callback to start, as in pinned
`KTask.ZC`. `Kill(wait=FALSE)` requests cooperative termination. Descendant
callbacks run before their parent's task storage is reclaimed. `ZcTaskRun` reports
`-2` when live tasks are all suspended or waiting rather than spinning forever.
`BirthWait` and `DeathWait(send_exit=FALSE)` park cooperative callers until
their task-pointer condition changes. A root wait with no runnable producer
fails the native session explicitly. `TaskWait` follows a task's input-filter
pointer and waits for an empty server
queue plus `TASKf_IDLE` (and optionally `TASKf_CMD_LINE_PROMPT`). The additive
`ZcTaskWaitTimeout` bridge call also returns false when a nonnegative
millisecond deadline expires. `ZcMessageGetTimeout` adds a bounded message wait
that returns zero on timeout without changing the upstream `MessageGet` API.
Each guest task starts with self-linked input-filter and empty queue heads. The
bridge can enqueue up to 128 pinned-layout `CJob` messages across tasks; `MessageScan`
consumes matching messages and discards excluded codes, while `MessageGet`
parks until a message arrives. When the current task scans its own queue,
`MessageScan` polls the device input bridge; a root `MessageGet` with a key
mask can therefore wait for a real virtio or serial key. When pinned
`sys_focus_task` names a live child, scheduler yields also poll and enqueue
device keys for that child, waking its parked `MessageGet`. Ending the focused
task clears the pointer. `MessagePostWait` waits until the recipient
becomes idle again. `KeyScan` and `KeyGet` consume the same key-down messages;
when invoked from a native guest call, they also poll virtio keyboard or
PL011 serial input. `TaskExe` queues source text for a server to compile when
it calls `JobsHandler` or scans its own message queue; a server marked
`TASKf_AWAITING_MESSAGE` parks until
its next job. Completed results can be scanned or awaited. This bootstrap
compiler engine is single-CPU, but each child now compiles into a symbol
table linked to its parent's table, as pinned `Spawn` does. This is not the
full ZealOS compiler or guest `CTask.hash_table` ABI. The implementation
accepts simple expression statements. It
supports `JOBf_FREE_ON_COMPLETE`, `JOBf_WAKE_MASTER` when the master is the
calling task, `JOBf_FOCUS_MASTER` when the master permits self-focus, and
`JOBf_EXIT_ON_COMPLETE` for child servers. A bounded `TaskText` path queues
source through one temporary input-filter task per server. Text runs in the
filter's inherited compiler namespace; queued messages return to the server when the
filter exits. It also handles queued executable jobs between text jobs and
returns their results to the master. `JOBf_HIGHEST_PRIORITY` waits for a
pending filter to complete before starting a new one. Concurrent/nested
filters, the Doc StdIn pipeline,
and other `JobRunOne` variants remain future work. A queued source job can
yield or sleep after its current statement has compiled, and its emitted code
can dispatch a nested job on the same task. Parsing and code emission remain
non-switching. `Exit` from emitted source ends a child and publishes zero for
an in-flight canceled `TaskExe` result. Killing an ancestor from emitted
source still fails the session explicitly and requires `zreset`.
`JobQueue` accepts the pinned `JOBT_CALL` signature for `target_cpu=0` only.
A reserved cooperative executive runs callbacks and returns results through
`JobResGet`; the pinned default target CPU 1 is unavailable because this
system has one guest CPU. The auxiliary arguments must retain their defaults.
`mp_count` reports 1. Precompiled CPU-0 callbacks can yield or sleep
cooperatively on the executive's stack; they still cannot self-kill or
recursively dispatch jobs in this bootstrap.
`Spawn` accepts the default target CPU (`-1`) or explicit CPU 0 and the normal
queue flag. Its 64 KiB default stack can be overridden up to 2 MiB; requests
below 64 KiB are rounded up to the bridge's minimum. Other CPU IDs and
alternate flags are rejected. `ZcTaskSpawn`/`ZcTaskYield`/`ZcTaskRun`/`ZcTaskResult` remain
temporary test bridges; `ZcTaskRun` pumps cooperative tasks to completion.
ARM64 atomic byte operations implement
`Bt`/`LBts`/`LBtr`, the physical counter supplies `TSCGet`, and an F64 host
conversion supplies `ToF64`.

## Acceptance

```sh
make check-upstream
make check-compat
make check-compat-pci
python3 scripts/check-compat.py --pci --probe-upstream
```

The two guest harnesses use disposable firmware variables and storage. They
exercise ISO boot and the UTM-shaped PCI/GPT boot image without modifying the
UTM VM or persistent RedSea image. Their new persistence gate writes source
to the scratch volume, restarts the guest, and runs it again. Logs are `build/check-compat.log` and
`build/check-compat-pci.log`. A headless pass does not prove the UTM app's display
and keyboard path; run `zcheck` there too after `make utm`.

Tests cover recursive QuickSort and callback ABIs, signed and duplicate keys,
record payload preservation, empty/singleton inputs, surrounding guard values,
shared globals and functions, relative includes, F64 calls/default arguments,
U32 overflow/layout, allocations larger than 64 KiB, arbitrary frees, and
compiler-error recovery via a fresh session, 24 nested functions and 12 classes,
constant comparison chains, allocation failure, and stable heap usage over
repeated sorts. Additional guest tests cover UTF-8 identifiers, file-scope
`public`, true and false `#assert` layout checks, class `$$` offsets and final
size, false-branch `#if` selection, quoted `#define` metadata, and three F64 functions with
conditional returns (the stale ARM64 emitter pointer regression). The guest also runs the original
boot regressions before reaching the shell.

The local-array bootstrap extension accepts a complete brace list for a
one-dimensional scalar array. It emits element stores at the declaration,
including expression values from the current call frame. `LocalArrayChecks`
tests I64, U32 truncation and F64 across repeated calls. It does not yet
accept partial, multidimensional or aggregate brace initializers.

Expected outputs are explicit assertions; this is **not yet a differential
comparison against a running x86 ZealOS**. More upstream modules and a reference
oracle are needed before broad language compatibility can be claimed.

## Boundaries

- `System/Bootstrap.ZC` aliases primitive types and declares bootstrap host APIs.
  It is not the real ZealOS `KernelA`/`KernelB`, primitive unions or full runtime.
- UTF-8 identifier bytes, file-scope `public`, and `#assert` now cover tested
  upstream forms. Class-scoped `$$` is checked for a nonnegative offset up to
  1 GiB and affects member offsets and class size; assigning it inside a union
  is still unsupported. Quoted `#define` category names are metadata and are
  ignored by the native compiler. The native session has no object-module export visibility;
  `public` only leaves a declaration in its global table. `#assert` evaluates
  through the current guest compiler and does not yet establish full ZealC
  compile-time semantics.
- Aiwnios has its own language dialect and ABI. The native local-array brace
  extension covers only one-dimensional scalar arrays with every element
  supplied. It is not a claim that the whole legacy frontend dialect or
  aggregate initializer semantics are available in the native compiler.
- The root and up to four live child `CTask` instances support explicit cooperative
  yields on one CPU. Completed slots can be reused; stale task pointers must
  not be retained. Their other fields are mostly zero. The bridge gives each
  task an allocation owner and reclaims its allocations on return or kill, but
  does not implement ZealOS heap sharing, documents, queues or windows.
  `Suspend` cannot suspend the root shell; `Kill` cannot kill it and rejects
  `just_break` because no debug exception runtime exists. `Exit` and
  `TaskEndNow` can terminate a child. A direct `Kill` without an end callback
  is synchronous. With a callback, `Kill(wait=TRUE)` waits until that callback
  starts; the callback may yield before task teardown, as in upstream ZealOS.
  Descendant teardown runs each child's end callback on its own task. There is
  no message-based exit or general-purpose wait queue yet. The explicitly named
  ARM64 bridge extensions `ZcTaskWaitTimeout` and `ZcMessageGetTimeout` provide
  bounded cooperative task and message waits.
  A later entry records a bounded cooperative `Sleep`.
  `DeathWait(send_exit=TRUE)` gives a not-yet-started target a cooperative
  slice so it can install its end callback, then requests the supported local
  teardown path; the full `XTalk` task-exit message protocol is not implemented.
  `BirthWait` and `DeathWait` park cooperative tasks; a root
  wait that cannot progress fails the native session instead of hanging. It
  also applies to `TaskWait`; a task that has ended or has an invalid input
  filter makes `TaskWait` return, as upstream does. Message delivery is
  cooperative and bounded to 128 queued jobs; input filtering only follows
  the direct task links, without the upstream popup/window behavior. Queued
  messages and pending source jobs are released when a task ends. An in-flight
  source job is completed with zero for a live master or waiting caller. The bounded
  `TaskExe` subset uses inherited per-task symbol tables and supports caller wake,
  focus return, and child-server exit. The bounded `TaskText` path uses one
  temporary input filter per server; a highest-priority request waits for the
  previous filter before starting a fresh one. Nested filters remain absent.
  The reserved CPU-0 executive accepts `JobQueue` function calls with zero
  or `JOBf_FREE_ON_COMPLETE` flags, and the default queued `SpawnQueue` path;
  SMP remains absent.
  The bridge uses fixed 64 KiB stacks and has no timer preemption, SMP, full
  upstream `Spawn`/scheduler modes, or the full ZealOS task scheduler.
  Native `KeyGet` and key-masked root `MessageGet` block for a real key; a child
  named by `sys_focus_task` can park and wake on a real device key. Without
  explicit focus, the task scanning its own queue owns device input. This is
  still cooperative polling, without upstream window hit testing or automatic
  focus selection. Printable echo is supported by `KeyGet`, but raw-cursor
  display is rejected. Serial input
  supplies key-down ASCII only, without scan codes or key-up events.
  Direct x86 FS/GS
  lowering remains rejected. Exception and interrupt
  transitions will need to account for the saved FP state as those services
  become real.
- Compiler/parser errors and allocator failures abandon the current session.
  Use `zreset` to discard it; successful previous definitions are not rolled
  back. This is not transactional module loading or CPU-fault containment.
- Code runs privileged. A bad pointer, division trap or infinite loop in guest
  source can still stop the VM. `zreset` is only useful while the shell runs.
- Arenas are bounded bootstrap storage, not a physical/virtual memory manager.
  They use the kernel's existing executable mapping; W^X is not implemented.
- Minimal compiler C support is not a general libc/libm. Power accepts integer
  exponents within a bounded range; unsupported fractional powers and certain
  nonfinite remainders explicitly fail. No general math-compatibility claim.
- The source archive is read-only. The native source store has two 32 MiB
  banks with append-only records, 95-byte paths and a 4 MiB per-file limit.
  `zedit` presents a fixed full-screen framebuffer source view. `j`/`k` move
  its selected line; `[`/`]` move by one visible page; `g`/`G` jump to the first
  or last line. The view follows the selection. `e <text>`, `n <text>`, and
  `x` edit, insert before, and delete that line. `p [line [count]]` selects a
  view and numbered-line commands remain available. A filled log reports an
  error without replacing earlier versions. Guest `zgc` reclaims old versions in the
  inactive bank, verifies the copy, flushes it, and commits the new
  superblock last. On virtio disks advertising FLUSH, saves and deletions
  also flush data before publishing a record header and flush the commit.
  A device without FLUSH can still save sources, but does not offer the same
  power-loss ordering; `zgc` refuses to switch banks there. Guest `zrm`
  appends a deletion record. `zput` remains capped by the
  512-byte shell line; `zrecv` streams larger files over serial to the native
  partition, and the stopped-VM
  host importer also accepts large files. This is bootstrap storage, not a
  general filesystem or editor. The 64 KiB/eight-entry RedSea volume
  remains for legacy demos. Full Doc/Gr APIs, Adam startup, kernel rebuild
  and installation remain unimplemented. The framebuffer shell keeps a
  retained text plane and scrolls long output there; verify long `help` and
  source-load output in UTM because serial-only checks cannot catch console
  redraw errors.

## USB direction: reuse YDE with ARM64 platform hooks

The first native USB backend now initializes the NEC/QEMU PCI xHCI models on
QEMU virt, enumerates root-port boot keyboards and unnumbered HID relative
mice/absolute tablets, and feeds the existing graphical input path. VirtIO
MMIO and independent serial input remain available. USB claims keyboard and
pointer ownership only after successful enumeration/configuration; the
VirtIO input transports are reset/parked while USB owns their capability.
QEMU [activates the VirtIO host handler](https://github.com/qemu/qemu/blob/v10.0.0/hw/input/virtio-input-hid.c)
at DRIVER_OK, so discarding its events
alone can starve USB of host keys. Disconnect/failure releases held keys/buttons,
reinitializes the parked VirtIO queues and returns ownership
to the recovery path. Root-port and USB2 hub changes are polled with a 100 ms
connect debounce; hub interrupt bitmaps trigger scans, backed by a periodic
status scan. Descendant slots are disabled before removing a hub.

`src/usb_platform.h` provides width-correct MMIO, explicit HHDM-to-physical
DMA addresses, cache maintenance/barriers, bounded timer waits, firmware BAR
mapping and reserved DMA allocation. It is intentionally a QEMU virt root-bus
backend; it does not configure a physical PCIe bridge or an IOMMU. The driver
supports two emulated controllers, eight devices, four interrupt IN endpoints per
device, 4 KiB controller pages and up to 32 scratchpads. A 1 MiB reserved DMA
arena supplies a 48 KiB region per device record. Disable Slot completion
and event draining allow that region to be reused on reconnect; uncertain
teardown quarantines it. Controller-owned allocations remain reserved.
`src/usb_xhci.h` adapts YDE's polled ring and
enumeration behavior; `src/usb_hid.h` isolates bounded report decoding from
hardware access. Unsupported layouts (including report IDs) are rejected.

The bootstrap graphical terminal now consumes key-down, key-up and menu
messages in one ordered scan. `MessageScan` discards messages outside its
mask; the earlier separate key-up/cleanup drains could discard a USB
key-down arriving between passes. FS/LS interrupt intervals round down to
the supported power of two so a 10 ms endpoint is serviced at 8 ms.

`make check-usb-input` tests NEC and QEMU models, USB-only input, relative
mouse/tablet decoding, actual framebuffer typing and cursors, source editing
and persistence, ring wraparound, duplicate suppression and VirtIO recovery.

## Native compiler-error recovery

Interactive `zc`, application `zload`, `ExePutS` / `ExeFile`, `ExePrint` and
source jobs now catch native lexer/parser/emitter exceptions at a statement
boundary. The error remains visible; `zc` / `zload` report failure, while the
native `ExePutS` boundary returns zero. The session's `failed` bit remains clear
and the task returns normally to its caller. Successfully compiled/executed
earlier statements remain committed, including definitions loaded before a
later statement fails. Internal bootstrap/service module loads retain their
existing fatal-load behavior.

The synchronous CPU-0 parser checkpoints allocator metadata, live data/code
arena prefixes, the compiler task, heap counters and parser depth state before
each parse/emission step. On a compiler exception it restores that state,
including existing extern/import patches, then frees the restored temporary
compiler and lexer (including unconsumed include/macro buffers). This removes
half-built definitions and preserves an older implementation after a failed
redefinition. Code-cache maintenance follows restoration.

The checkpoint is committed before emitted code runs; runtime execution can
yield or invoke another file, and another task may then own the shared recovery
buffer. Parsing/emission cannot switch tasks. Allocated fiber-stack payloads
and the allocation containing the active native stack pointer are excluded
from restoration, while their allocator headers are restored. Both ordinary
fiber stacks and explicitly allocated `CallNOnStack` stacks are exercised.
Shell compiler entry points reject calls made from code being evaluated during
parsing, before replacing either recovery guard. This keeps a compile-time
callback from overwriting the outer statement checkpoint.

Recovery reserves 24 MiB outside the managed arenas. Copies cover live prefixes
and allocator headers rather than the unused arena tails. The managed 16 MiB
data and 8 MiB code limits remain unchanged. `zstatus` exposes the number of
recovered errors and whether the parser recovery boundary is active.

The lexer now clears its lookahead character at EOF, preventing a missing final
newline from repeating a stale token until the arena is exhausted. Macro
expansion after the source file has ended no longer dereferences a null file
stack; malformed strings, comments and directives can reach the recovery path.

This handles compiler exceptions, not arbitrary runtime faults. Allocator
invariants/exhaustion, unresolved runtime calls and uncaught runtime exceptions
retain the failed-session behavior. Runtime exception unwinding across an
`ExePutS` host invocation, general upstream Compiler/Break catch semantics,
compiler option/metadata integration, preemption and full upstream startup
remain work. External side effects of code evaluated by the compiler are not
transactional.
